# Agent Note: 在待切换模型前压缩并落地截断摘要

Status: implemented

[English](2026-09-10-compaction-model-switch-and-truncated-summary.md) | 中文

## Problem

从大模型切到小模型时，预步骤压力仍按上一次请求头计价，溢出请求会先发出。手动 `/compact` 随后套用压缩模块自带的 8192 输出上限，并在 `max-tokens` 结束时丢弃摘要，即使已经有文本。思考模型会把该上限花在推理上，压缩控件便报告无法产生有用摘要。

## Decision

预步骤压力在存在尚未落地的 `model/selection` 时按它计价，否则使用最新请求头。溢出恢复仍使用该请求头，再回退到 AgentOptions。未设置 `maxTokens` 时，摘要调用沿用适配器默认值。`max-tokens` 结束会落地已生成的文本；空截断结果仍会失败关闭。

## Alternatives considered

**继续按上一次请求头计价压力：** 否决，因为 UI 切模型在 `agent/pre-step` 时还不是请求头，小模型窗口不会在溢出请求发出前触发压缩。

**按 AgentOptions 计价压力：** 否决，因为这些字段是创建时的默认值，不是当前选择器。

**保留 8192 摘要上限并在截断时失败关闭：** 否决，因为隐藏推理 token 会耗尽该上限，压缩命令随后会让对话保持不变。

**一律接受截断摘要，包括空输出：** 否决，因为空检查点不能替换被遮蔽的区间。

## Consequences

大模型切到小模型会在下一次请求前按即将使用的窗口压缩。手动压缩可以在思考模型上完成。显式配置的 `maxTokens` 仍是上限。非空但被截断的检查点可能缺少靠后的摘要章节。
