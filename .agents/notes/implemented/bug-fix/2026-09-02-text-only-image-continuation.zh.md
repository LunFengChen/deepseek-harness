# Agent Note: 在纯文本模型切换后继续会话

Status: implemented

[English](2026-09-02-text-only-image-continuation.md) | 中文

## 问题

会话可能在早先使用支持视觉的模型时已经持久化图片块。之后选择纯文本模型，后续提示词会在准入阶段失败；即使命令的文本本身可以执行，只要图片草稿存在，命令提交也可能被拦截。图片历史对会话仍然有效，但它不应成为当前路由必须支持图片的理由。

## 决策

图片能力在最终 LLM 分发投影阶段执行，而不是在提示词准入阶段执行。纯文本路由会把直接图片和嵌套工具结果中的历史图片替换为确定性的文本占位符；只追加的会话日志与输入框中的图片草稿保持不变。用户消息准入仍会先完成持久图片校验和附件保存。

当命令路由没有声明接受图片时，斜杠命令继续执行。命令 source 发出信息级提示，在不序列化图片的情况下执行文本，并让图片草稿继续保留。声明接受图片的命令仍然会收到序列化后的图片。

适配器仍是按路由执行的最终强制点。错误声明图片能力的提供方仍可能拒绝请求；修正该元数据后，后续请求会使用纯文本投影。

## 曾考虑的替代方案

**自动切换到支持图片的模型。** 这会覆盖用户明确的模型选择，并可能意外改变费用、行为或凭据，因此改为尊重当前选择的模型。

**选择纯文本模型时删除或重写图片历史。** 这会丢失持久用户数据，并使之后切回视觉模型变得不可逆。请求期投影可以保留历史，供未来支持视觉的路由使用。

**只要存在图片就拒绝整个提示词或命令。** 这会让无关的历史图片或草稿阻塞文本工作。现在准入阶段只校验自己负责的内容，由最终请求投影处理模态差异。

## 后果

即使会话历史包含图片，从支持视觉的模型切换到纯文本模型后仍可继续会话。纯文本请求携带稳定的图片文本说明，而不是视觉负载。不支持图片的命令会执行文本并保留图片，因此用户无需重新附加图片即可切换命令或模型。信息级提示不表示图片已被删除。
