# Agent Note: 会话轮次尾部的真实删除

Status: implemented

English | [中文](2026-09-02-destructive-session-tail-deletion.md)

## Problem

Fork 会话删除不满意回答的速度太慢，而且保留原会话中的不满意事件会让后续模型请求继续携带这些历史记录。

## Decision

会话控制器提供 `deleteFrom`，把选中的可见消息定位到所属的 `turn/start`。服务先刷新待写入事件，将 JSONL 文件原子重写为保留前缀，再截断内存中的 `Session` 并重置所有派生投影。发起操作的客户端成功后重新同步会话，因此下一次请求和当前 transcript 只使用保留的历史。

Web 聊天为已持久化的用户和助手轮次显示垃圾桶图标。点击图标后打开带确认勾选框的二次确认对话框；确认后永久删除选中轮次及其后所有事件。Agent 运行期间拒绝删除，fork 继承的事件也不能删除。不支持重写的后端会明确失败，不会伪装成删除成功。

## Alternatives considered

**Fork 一个替代会话。** 这种做法会保留原历史，并继续承担促成本功能的慢速 fork 路径。

**只在 Web 客户端隐藏消息。** 被隐藏的记录仍会出现在后续模型请求中，也仍然持久化，因此不是真删除。

**只删除选中的消息事件。** 消息事件属于包含工具和边界记录的完整轮次，保留半个轮次可能导致回放或模型历史无效。按轮次删除可以保留合法的事件前缀。

## Consequences

删除不可撤销；选中轮次及其后的记录会从持久化文件和内存会话中消失。当前客户端会立即重新同步，其他已打开的客户端在会话改变后需要重新加载。JSONL 后端通过 rename 发布已同步的临时文件，重写失败时保留旧文件。
