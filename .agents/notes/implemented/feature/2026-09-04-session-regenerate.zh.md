# Agent Note：在当前会话重新生成回合

Status: implemented

English | [English](2026-09-04-session-regenerate.md)

## Problem

用户可以永久删除不满意的问题及其后续历史，但重新提交同一个问题仍需要较慢的 fork，并且原会话不容易继续使用。历史图片还是持久化引用，不能直接提交给浏览器 prompt API。

## Decision

Chat UI 在持久化的用户消息和 steering 消息上提供刷新操作。用户确认风险后，客户端先把所有持久化图片引用重新解析为 prompt 内容，再永久截断选中消息及其后的历史，最后在同一会话中将重建的问题排队提交。如果图片无法读取，则不删除历史，并把失败报告到控制台。

该能力直接实现于第一方 Chat 插件，而不是引入独立的会话操作插件。这样删除与重新生成共用同一个 Session Controller 接口，并保留现有不支持图片模型的历史图片文本化处理。

## Alternatives considered

**fork 会话后在新会话提交问题。** 否决，因为速度更慢，而且用户得到的是第二个会话，不是替换原失败尾部。

**只提取文字重新提交。** 否决，因为这会静默丢弃用户原本附带的历史图片。

**先删除再读取附件。** 否决，因为 prompt 重建失败后将无法再取得持久化引用。

**安装外部删除/重新生成插件。** 否决，因为删除已经是原生 Session Controller 操作，第一方实现可以保持相同的运行时、图片和模型切换语义。

## Consequences

- 重新生成是永久操作：选中的用户消息及其后的所有事件会在替代 prompt 排队前被删除。
- UI 使用现有垃圾桶确认界面，并用刷新图标提供同样的风险确认。
- 历史图片会在截断前重新上传为 prompt 数据；不支持图片的模型仍可通过现有纯文本投影路径继续工作。
- 图片读取失败时历史保持不变；删除成功后 prompt 提交失败则由会话错误路径和控制台诊断呈现。
